# Freshsales Name Checker 1.2.1

Розширення Chrome/Edge для локальної перевірки імені з картки Contact info у Subject та першому непорожньому рядку відповіді. Працює лише на `bbq1-465157612863820669.myfreshworks.com/crm/messaging/`.

## Встановлення або оновлення

1. Розпакуйте `name-checker-extension.zip`.
2. Відкрийте `chrome://extensions` (Edge: `edge://extensions`), увімкніть режим розробника.
3. Для першого встановлення: «Завантажити розпаковане» → папка `extension`.
4. Для оновлення: замініть файли у встановленій папці та натисніть кнопку оновлення розширення. Переконайтеся, що відображається версія **1.2.1**.
5. Перезавантажте Freshsales.

## Кольори Send

- **Червоний:** хоча б одне розпізнане ім’я не збігається з карткою.
- **Жовтий:** немає явної розбіжності, але не вдалося перевірити обидва поля (порожній лист, невідоме звертання, недоступна картка/редактор або тема).
- **Початковий колір сайту:** і Subject, і звертання відповідають картці.

Поруч із Send є кнопка **«Перевірити ім’я»** та короткий статус. Після натискання одразу виконується перевірка; спінер та напис «Перевіряю…» показуються 0,6 секунди для зворотного зв’язку. Анімація враховує prefers-reduced-motion. Текст Send білий у звичайному та червоному станах і темний на жовтому фоні. Наведіть курсор на статус, щоб побачити результат окремо для Subject і першого рядка. Перевірка також автоматична після вводу, вставки тексту, зміни картки або вкладки, із затримкою 180 мс.

Перевіряється **Reply та новий лист**. У **Private Note** перевірка вимкнена, додаткові елементи прибираються, колір Send відновлюється. Розширення не змінює чернетку, не надсилає листи та не блокує Send. Червоний/жовтий колір — попередження, а не блокування.

## Як читаються дані

Адаптер відповідає структурі двох наданих збережених сторінок: `fw-email-composer` → вкладені відкриті Shadow DOM `fw-email-header` / `fw-input#subject-field`, `fw-froala-editor` → iframe, `fw-froala-footer` → `fw-button#btnSendEmail` → справжня кнопка.

У новому листі читається поточне значення видимого поля Subject. У Reply, де такого поля немає, береться тема з заголовка поточної розгорнутої переписки, а не з бічного списку чи старих повідомлень. Префікси `VIP Success Team -`, `Re:`, `Fw:` та `Fwd:` відкидаються в обох порядках, зокрема `VIP Success Team - Re: Kirsty, …`. Старий прихований MediumEditor та історія листування не перевіряються.

Ім’я в картці може містити email: він відкидається. Підтримуються `Hello Oscar,`, `Hi Oscar,`, `Dear Oscar Clarke,`, Good morning/afternoon/evening, Привіт/Вітаю/Шановний/Шановна та тема `Oscar, текст теми`. Регістр не враховується. Транслітерації, пестливі форми та кличний відмінок автоматично не прирівнюються. Довільний текст без розпізнаного звертання дає жовтий статус. Повідомлення без імені не вважається успішно перевіреним.

Без сервера, мережевих запитів, телеметрії, сховища, фонових процесів і зовнішніх бібліотек у розширенні. Використовуються події та MutationObserver у потрібних компонентах; постійного опитування немає. CPU/RAM на живому Freshsales не вимірювалися.

## Перевірки для розробки

Збірка не потрібна. Використовуйте поточний checkout без створення worktree.

```sh
node tests/checker.test.cjs
node --check extension/content.js
# jsdom потрібен тільки для DOM-тестів, у ZIP розширення він не входить:
npm install --prefix /tmp/name-checker-tools --no-audit --no-fund jsdom@30.1.3
NODE_PATH=/tmp/name-checker-tools/node_modules node tests/dom.test.cjs
```

DOM-тести відтворюють вкладені Shadow DOM із прикладів, перевіряють обидва поля, події в iframe, ручну перевірку, зміну картки, перемикання Reply/Private Note та відновлення кольору. Фікстура знеособлена. Збереження сторінки не містить тексту документа `about:blank` iframe: тести вставляють туди контрольні чернетки. jsdom не перевіряє реальну геометрію чи CSS браузера. Перевірка встановленого розширення в авторизованому Freshsales залишається потрібною.
